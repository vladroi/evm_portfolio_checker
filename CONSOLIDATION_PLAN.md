# Следующий этап: консолидация средств собственных кошельков

Это дизайн **отдельного** приложения, не включённого в сканер. Текущий пакет не умеет переводить средства.

## Цель и границы

- Все исходные кошельки принадлежат оператору либо оператор имеет явное разрешение распоряжаться ими.
- Вход: адреса, результаты сканирования без ошибок, независимая проверка балансов прямо перед каждой транзакцией, подтверждённый адрес получателя и список сетей.
- Один `0x`-адрес получателя возможен для нескольких EVM-сетей, но **это всё ещё разные сети**. Для объединения балансов в *одну конкретную сеть* потребуется отдельный мост/обмен и оценка рисков.
- `dry-run` по умолчанию. Только явное подтверждение исполнения. Без автоматического sweep всех адресов из неизвестного списка.

## Требования к безопасному исполнителю

1. **Кошельки:** encrypted keystore или hardware signer; сверка полученного адреса с разрешённым исходным адресом; не хранить seed/private key в `addresses.txt`, логах, CSV или репозитории.
2. **План:** `chain_id`, `source`, `destination`, `token_contract`, `amount_raw`, текущий баланс, gas_estimate, fee_cap, резерв нативного токена, ориентировочная остаточная сумма и статус. План сохранять в JSON для проверки пользователем до отправки.
3. **Фильтр:** если какая-либо проверка этой позиции дала `ERROR`/`UNAVAILABLE`, не выполнять перевод по ней. Игнорировать спам-токены, которые могут иметь блокировки, комиссии за перевод или иной нестандартный код.
4. **Комиссии:** оценивать `eth_estimateGas`, EIP-1559 и L2-специфику (например, стоимость публикации L1-данных). Не рассчитывать перевод нативной монеты как `balance - 21000 * фиксированная комиссия` во всех сетях; комиссия может меняться.
5. **Порядок:** ERC-20/BEP-20 сначала; нативная монета последней. Если для токенов нет нативного газа — пометить `NEEDS_GAS`, не делать рискованных автоматических пополнений.
6. **Отправка:** явный `--execute`, whitelisted recipient, отдельное подтверждение пользователем, уникальные nonce под блокировкой на адрес/сеть, transaction signing без передачи ключа RPC-провайдеру.
7. **Подтверждение:** сохранять tx hash, получать receipt, проверять `status == 1`, при необходимости ждать достаточное число подтверждений. Не считать отправленную транзакцию успешно завершённой до получения receipt.
8. **Идемпотентность:** журнал tx hash / chainId / nonce на диске. При рестарте проверять прошлые транзакции, а не повторно отправлять тот же перевод вслепую.
9. **Остаток:** рассчитывать и показывать минимальный разумный остаток после газа; идеальный ноль в каждой сети не гарантирован из-за изменяющейся комиссии/специфики L2 и «пыли».
10. **Экономичность:** не переводить токены, у которых прогнозируемые gas/bridge комиссии дороже стоимости перевода; явно показывать это оператору.

Нельзя считать скан из выборки известных токенов полным инвентарём портфеля: до консолидации нужно добавить проверку по индексатору или ограничить сбор явно перечисленными известными токенами.
