EVM Consolidator — восстановление зависших переводов / быстрый запуск

Скопируйте в существующий проект три файла из этого архива:
  start.py
  consolidator.py
  meme.py

НЕ заменяйте settings.json, addresses.txt, private_keys.txt, networks.json,
tokens.json. НЕ удаляйте папки reports и consolidation, в частности
consolidation/plan.json и consolidation/journal.jsonl.

Дождитесь, пока прежний python start.py завершится, или остановите его до
этапа подтверждения, если оно зависло при проверке MEME. Не запускайте два
экземпляра консолидатора одновременно.

Запуск: python start.py

Изменения:
1. MEME проверяется только для адресов, ключи к которым загружены локально,
   а не для всей таблицы из 897 публичных адресов. Это сокращает запуск.
2. После одного общего подтверждения ранее 'uncertain' транзакции
   проходят автоматическую сверку по старым хешам и nonce на минимум двух
   отдельных RPC. Если хеш не найден, отправитель/цепочка/адрес получателя
   совпадают с планом и latest=pending=сохранённый nonce, разрешена ОДНА
   повторная попытка с ТЕМ ЖЕ nonce (не новым). Если данных недостаточно,
   pending виден или nonce другой — операция остаётся заблокированной.
3. Обе попытки сохраняются в неизменяемом журнале, восстановление повторно
   не запускается автоматически после первой попытки.
4. Сверка reconcile проверяет также исходный хеш после замены.
5. Таблицы результатов создаются прежним report.py.

Замечания:
* Отсутствие транзакции в обозревателе само по себе не равно отмене.
  Проверка nonce не допускает двух подтверждённых операций с тем же nonce,
  но не гарантирует, что новая попытка будет принята узлами.
* При ошибках RPC или недостаточном газе скрипт безопасно пропускает
  такую операцию и продолжает остальные.
* Файлы не содержат приватных ключей. Никогда не загружайте private_keys.txt
  в Git / облако. Этот режим использует незашифрованный локальный файл.
* 47 локальных автономных тестов пройдены, но реальная отправка с данной
  версией не выполнялась: используйте на свой риск, сверяйте получателя.
